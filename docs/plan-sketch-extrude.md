# 다음 변경 단위 계획: 치수형 사각형 → 4 mm 돌출 → 폭 수정 → 재계산 → 저장·재열기

상태: **계획 (구현 전)**. 전제: `docs/baseline.md` 의 기준선과 첫 명령 경로(명령 봉투·리비전)가 통과한 상태.

## 1. 목표 시나리오 (완료 기준)

1. XY 평면 스케치에 **치수형 사각형**(폭 60, 깊이 40)을 그린다.
2. 그 사각형을 **4 mm 돌출**해 판을 만든다.
3. 스케치의 **폭 치수만 80 으로 수정**한다.
4. 판이 **80×40×4 로 재계산**된다 (서버 CadQuery, 브라우저 manifold 모두).
5. **저장 → 다시 열기** 후에도 스케치·치수·돌출이 그대로이고, 폭을 다시 수정하면 재계산된다.

이어서 같은 단위 안에서: **기준 판 샘플**(형식 2)과 **실패 복구**(계산 실패·오래된 결과·잘못된 파일)를 검증한 뒤 → **관통 구멍**(원 스케치 + 관통 컷) → **STL 출력 검사**(치수·닫힌 메시·출력 전 검사) 순서로 추가한다.

## 2. 설계안 (기존 구조 재사용)

### 2.1 설계 원본 (형식 2)
```jsonc
"model": {
  "schemaVersion": 2,
  "units": "mm",
  "sketches": [{
    "id": "sk1", "name": "판 윤곽",
    "plane": { "type": "XY", "offset": 0 },          // 처음엔 XY 평면만
    "entities": [{ "id": "r1", "type": "rectangle", "center": [0, 0] }],
    "dimensions": [                                   // 치수 = 이름 붙은 파라미터
      { "id": "r1.width", "entity": "r1", "kind": "width", "value": 60 },
      { "id": "r1.height", "entity": "r1", "kind": "height", "value": 40 }
    ]
  }],
  "objects": [{
    "id": "plate", "kind": "extrude", "name": "판",
    "extrude": { "sketch": "sk1", "profile": "r1", "distance": 4 },
    "transform": { "position": [0,0,0], "rotation": [0,0,0] }
  }]
}
```
- 스케치는 객체 목록과 **별도 원본**(`sketches`)으로 둔다. 돌출 객체는 스케치를 **참조**한다 → 치수를 바꾸면 돌출이 따라온다 (파라메트릭).
- 돌출 객체는 기존 객체 체계(변환, 불리언, 출력 검사, 형상 키 캐시, 내보내기)를 그대로 쓴다. 관통 구멍 = 원 스케치 돌출을 `cut` 의 도구로.
- 원점 규칙 유지: 돌출 객체의 로컬 원점 = 스케치 평면의 원점, 돌출 방향 = 로컬 +Z.
- **메시 편집(이후 단계)과의 분리**: CAD 피처(스케치·돌출·불리언)와 메시 토폴로지는 서로 다른 원본으로 둔다. CAD → 메시는 "굽기"(한 방향 변환)이며, 메시 편집 결과가 CAD 피처를 덮어쓰지 않는다.

### 2.2 명령 (모두 `submit` 봉투 경로)
| 명령 | 입력 |
|------|------|
| `create_sketch` | `id, name?, plane` |
| `add_rectangle` | `sketch, id, center, width, height` (치수 2개 자동 생성) |
| `set_dimension` | `sketch, dimension, value` |
| `extrude` | `id, name?, sketch, profile, distance, position?` |

- 실행기 검증: 없는 스케치·프로파일, 0 이하 거리, 돌출 참조 중인 스케치/프로파일 삭제 거부.
- 스키마 단일 출처 규칙 그대로: Zod → `schema:export` → Pydantic → 계약 테스트. AI 도구에도 자동 노출.

### 2.3 CAD 엔진
- 서버: `cq.Workplane("XY").rect(w, h).extrude(d)` (원은 `.circle(r)`).
- 브라우저: `CrossSection.square([w, h], true).extrude(d)` / `CrossSection.circle`.
- 공유 픽스처 `model-sketch-plate.json`(프론트 실행기로 생성)로 두 엔진의 치수·부피를 각각 검사 (기존 `model-cut-rotated.json` 방식).
- 형상 키: 돌출 객체의 키에 참조 스케치의 프로파일 치수를 포함 → 폭 수정 시에만 재계산.

### 2.4 저장 형식 마이그레이션 (v1 → v2)
- `formatVersion: 2`, `model.schemaVersion: 2`. 읽기: v1 파일은 `migrate()` 로 `sketches: []` 를 붙여 v2 로 연다 (객체는 그대로).
- 쓰기: 항상 v2. 저장하기 전까지 원본 파일은 바뀌지 않는다 (열기는 읽기 전용).
- 검증: `shared/samples/project-v1-e0ac5e7.ai3d` 복사본 → 열기(마이그레이션) → 저장(v2) → 다시 열기 → 설계 동일. 손상·미래 버전 파일은 열지 않고 현재 작업 유지.
- 구버전 앱이 v2 파일을 열면 기존 동작대로 "더 새로운 버전" 안내 (`parseProject`).

## 3. 검증 계획

| 단계 | 테스트 |
|------|--------|
| 실행기 | 사각형·치수·돌출 생성, 치수 수정 → 같은 객체 유지, 잘못된 참조·음수 거리 거부, 봉투(중복·오래됨) |
| 두 엔진 | 60×40×4 → 80×40×4 바운딩 박스·부피 (서버 pytest, 브라우저 vitest) |
| 형식 | v1 샘플 마이그레이션 왕복, v2 기준 판 샘플(`project-v2-plate.ai3d`) 왕복, 잘못된 파일 거부 |
| 실패 복구 | 계산 실패 시 이전 메시 유지·원본 보존, 오래된 결과 폐기(`runEvaluation`), 저장 실패 시 기존 파일 보존 |
| UI (E2E) | 사각형 그리기 → 돌출 4 → 폭 80 → 화면 메시 80 → 저장 → 새 프로젝트 → 열기 → 폭 90 → 재계산 |
| 이후 | 관통 구멍(원 스케치 컷) → STL: 치수·닫힌 메시·출력 전 검사 ✓ |

## 4. 결정이 필요한 사항

1. **스케치 범위**: 처음은 "치수형 사각형·원 + 고정 치수"만 (구속 해석기 없음) 으로 하고, 일반 구속 해석기(직선·호·일치·평행 등)는 다음 단계로 미룰지.
   - 권장: 미룸. 해석기 후보(예: planegcs WASM)는 라이선스(LGPL)·크기 검토가 필요.
2. **스케치 UI**: 첫 단계는 속성 패널에서 치수 입력으로 사각형을 만들고, 뷰포트에서 직접 그리기(클릭-드래그)는 다음 단계로 할지.
3. **리비전·명령 기록 저장 여부**: 형식 2 에 리비전(또는 명령 로그)을 함께 저장할지. 권장: 아직 저장하지 않음 (이력은 세션 메모리).
4. **AI 적용의 오래된 결과 정책**: AI 요청 후 사용자가 편집해 리비전이 바뀐 경우, AI 명령을 거부하고 다시 요청을 안내할지(권장, 이번 봉투 경로와 일관) 또는 최신 모델에 재적용할지.
5. **기존 박스와의 관계**: 기존 `box` 는 유지하고 돌출은 새 종류로 추가(권장, 기존 파일 호환), 또는 박스를 "사각형 스케치 + 돌출"로 통일할지.
