# 설계: 면 위 스케치 (기존 형상의 면에 스케치를 붙이기)

상태: **설계 (구현 전)** · 관련: `docs/plan-sketch-extrude.md`, `docs/architecture.md` "스케치와 돌출"

## 1. 목표

"판 윗면에 원을 그려 기둥을 세운다", "상자 옆면에 구멍을 뚫는다"처럼 **이미 있는 형상의 면을 골라 그 위에 스케치**한다.
판 두께나 위치를 바꾸면 그 면에 붙은 스케치와 그 위의 형상도 **따라 움직여야** 한다 (파라메트릭).

## 2. 문제: 면 번호는 형상이 바뀌면 달라진다 (실측)

CadQuery/OCCT 의 면 번호로 "윗면(+Z 평면)"을 찾으면 (`backend` 에서 측정, 2026-11-03):

| 형상 | 면 수 | 윗면 번호 |
|------|------|-----------|
| 박스 30×20×10 | 6 | 5 |
| 같은 박스, 폭 40 | 6 | 5 |
| 같은 박스 + 필렛 2 | 26 | **10** |
| 같은 박스 − 원통 구멍 | 7 | **2** |

- 필렛·불리언 한 번이면 번호가 바뀐다. "면 5에 붙은 스케치"는 다른 면으로 옮겨 가거나 사라진다 (CAD 의 "위상 이름 문제").
- 브라우저 엔진(manifold)은 B-rep 면이 없고 삼각형만 있다 → **두 엔진이 같은 규칙으로 해석할 수 있는 면 참조가 필요**하다
  (CLAUDE.md 2장: "CAD 엔진 구현은 같은 설계 원본을 같은 규칙으로 해석").

## 3. 선택지

| 안 | 방식 | 형상 변경에 견딤 | 두 엔진 동일 | 구현량 | 판단 |
|----|------|------------------|-------------|--------|------|
| A | OCCT 면 번호 저장 | ✗ (위 표) | ✗ (브라우저에 면 없음) | 적음 | 기각 |
| B | **피처 정의로 정한 "이름 있는 면"** (객체 + 면 이름: `top`, `+X`, `end` …) | ✓ (치수에서 계산) | ✓ (설계 원본만으로 계산) | 중간 | **권장** |
| C | 기하 선택자 (`>Z`: 법선이 +Z 인 가장 높은 면) | △ (불리언 후 대상이 바뀔 수 있음) | ✗ (브라우저는 메시에서 다시 구해야) | 중간 | 보류 |
| D | 위상 이름 추적 (OCCT TNaming, FreeCAD 방식) | ✓ | ✗ (서버 전용) | 매우 큼 | 기각 (현 단계) |

## 4. 권장안 B: 이름 있는 면에 붙는 스케치 평면

### 4.1 형식 (형식 v3 후보)

```jsonc
"plane": { "type": "face", "object": "plate", "face": "top", "offset": 0 }
```

- 면 좌표계는 **객체의 피처 정의(파라미터·스케치 치수)와 월드 변환**만으로 계산한다. 메시·B-rep 을 보지 않는다.
- `offset` 은 그 면의 바깥 법선 방향 거리. 스케치 (u, v) 축은 표의 규칙으로 고정.

| 객체 종류 | 면 이름 | 원점 (객체 로컬) | 법선 | u 축 |
|-----------|---------|------------------|------|------|
| box | `top` / `bottom` | (0,0,h) / (0,0,0) | +Z / −Z | +X / +X |
| box | `+X` `−X` `+Y` `−Y` | 각 면 중심 | 해당 축 | 면 위 수평 방향 (오른손 규칙) |
| cylinder·cone | `top` / `bottom` | (0,0,h) / (0,0,0) | +Z / −Z | +X |
| extrude | `end` / `start` | 단면 중심 + 법선×거리 / 단면 중심 | 돌출 방향 / 반대 | 스케치 u |
| extrude (사각형 단면) | `+u` `−u` `+v` `−v` | 각 옆면 중심 | 해당 방향 | 돌출 방향과 직교하는 수평 |
| sphere | (없음) | — | — | — |
| boolean | 기준(base) 객체의 면을 그대로 위임 | — | — | — |

- 필렛·모따기는 면 좌표계를 바꾸지 않는다 (면의 원래 평면 위치 기준). 구멍이 그 면을 뚫어도 평면은 그대로다.
- 원점은 면의 중심 → 판 폭을 80→90 으로 바꾸면 윗면 중심에 있던 기둥은 그대로 중심에 남는다.

### 4.2 의존 관계 규칙

- 스케치 → (붙은) 객체 → 그 객체가 쓰는 스케치 … 순환 금지. 예: 판 스케치를 판 자신의 윗면에 붙이면 거부.
- 붙은 객체를 삭제하려 하면 거부 (먼저 스케치를 다른 평면으로 옮기거나 삭제) — 현재 "돌출이 쓰는 스케치 삭제 거부"와 같은 방식.
- 메시 계약 유지: 돌출 객체의 메시는 여전히 **객체 로컬 좌표**. 붙은 스케치의 월드 좌표계를 돌출 객체의 월드 변환 역으로 옮겨 계산한다.
  형상 키에 "붙은 객체의 면 좌표계(월드)"를 넣는다 → 판을 옮기면 그 위 기둥만 다시 계산.

### 4.3 두 엔진
- 공통 함수 하나(`faceFrame(model, object, face)`)를 프론트(Three.js 행렬)와 백엔드(Python)에 같은 표로 구현하고,
  공유 픽스처(`model-face-sketch.json`: 판 윗면 기둥 + 옆면 구멍 + 회전한 판)로 바운딩 박스·부피를 양쪽에서 검사한다 (지금의 평면 픽스처 방식).

### 4.4 UI
- 객체 선택 → 속성 패널 "이 면에 스케치: 윗면 / 아랫면 / 옆면…" 버튼.
- 뷰포트: 그리기 도구 중 객체를 클릭하면 맞은 지점의 **법선과 객체 정의**로 가장 가까운 이름 있는 면을 고르고 그 면에 스케치를 만든다
  (메시 법선은 "어느 이름 면인지" 고르는 데만 쓰고, 저장하는 것은 이름이다).

### 4.5 AI
- 프롬프트에 면 이름 표를 추가. 검증기는 객체 종류별 허용 면 이름과 순환을 검사.

### 4.6 형식 마이그레이션
- 평면 종류가 늘어나므로 **형식 v3** 로 올린다 (구버전 앱이 열면 "더 새로운 버전" 안내). v2 → v3 는 내용 변경 없음.
- `shared/samples/project-v2-plate.ai3d` 로 v2 → v3 열기·저장 왕복 검사.

## 5. 검증 계획

| 단계 | 검사 |
|------|------|
| 면 좌표계 | 종류·면 이름별 원점·법선·u 축 (단위 테스트, 프론트·백엔드 같은 표) |
| 견고성 | 판에 필렛·구멍·폭 변경·이동·회전 후에도 윗면 기둥 위치·높이 유지 (두 엔진) |
| 의존 | 순환 거부, 붙은 객체 삭제 거부, 실행 취소 |
| UI (E2E) | 판 선택 → 윗면 스케치 → 원 그리기 → 돌출 → 판 두께 4→6 → 기둥이 따라 올라감 → 저장·다시 열기 |
| 출력 | STL 치수·닫힌 메시, 출력 전 검사 |

## 6. 결정이 필요한 사항

1. **권장안 B 채택 여부** (이름 있는 면만 지원, 불리언 결과의 임의 면은 기준 객체 면으로만).
2. **형식 v3 로 올리는 시점**: 이 기능과 함께 (권장).
3. **곡면(원통 옆면) 스케치**: 이번 범위에서 제외 (권장). 평면만.
