# 개발 계획

## 1. 기획서 기술 검토 (요약)

기획 방향(“AI는 JSON 명령만 생성 → 서버 검증 → CAD 커널 실행”)은 상용 CAD로 가기에 옳은 구조다. 다만 아래 사항을 초기에 확정해 두어야 나중에 재작성을 피할 수 있다.

| # | 항목 | 결정 / 권장 | 이유 |
|---|------|-------------|------|
| 1 | 좌표계 | **Z-up, 오른손, mm, degree** | CadQuery/OCCT, STL/3MF, 슬라이서가 모두 Z-up. Three.js도 `Object3D.DEFAULT_UP=(0,0,1)`로 통일 (`src/cad/zUp.ts`). |
| 2 | 도형 원점 | 모든 기본 도형은 **바운딩 박스 바닥면 중심**, 원통·원뿔 축은 로컬 Z | `position.z=0`이면 출력 베드 위. CadQuery `centered=(True,True,False)` / `makeCylinder`·`makeCone`과 동일. |
| 3 | 스키마 단일 출처 | 1주 차는 Zod가 원본, 3주 차에 **JSON Schema로 내보내 `shared/schemas/`에 커밋**, Pydantic 모델은 그 스키마를 기준으로 테스트 | 프론트/백엔드 스키마 불일치는 가장 흔한 버그원. CI에서 두 쪽이 같은 픽스처를 통과하는지 검사. |
| 4 | 명령 목록 보완 | 기획서 목록에 **`set_params`, `set_transform`, `rename_object`, `duplicate_object`, `delete_object`** 추가 | “높이를 50mm로” 같은 수정 요청은 파라미터 변경 명령이 없으면 표현할 수 없음. `export_stl`은 모델을 바꾸지 않으므로 명령이 아닌 별도 API(`/api/export`)로 분리 권장. |
| 5 | 히스토리 | 명령 + 모델 스냅샷 저장 | 명령 로그 = FeatureHistory 원천, 스냅샷 = 즉시 undo/실패 복구. 모델이 커지면 구조적 공유/주기적 체크포인트로 최적화. |
| 6 | 렌더링 경로 | 1주 차: 클라이언트 미리보기 → 2주 차: **백엔드가 계산한 메시(RenderMesh)를 표시** | 필렛·Boolean은 브라우저에서 정확히 재현 불가. 화면과 출력 결과가 같아야 신뢰가 생김. |
| 7 | CAD 실행 격리 | CadQuery 연산은 **별도 워커 프로세스 + 타임아웃** | OCCT는 C++ 크래시/무한 루프가 가능. API 프로세스와 분리해야 서버 전체가 죽지 않음. |
| 8 | 라이선스 | CadQuery(Apache-2.0), OCCT(LGPL-2.1 + 예외) | 상용 판매 시 OCCT 동적 링크 유지 + 고지 필요. Tauri 배포 시 Python 런타임 번들 방식(PyInstaller 등) 사전 검증 필요. |
| 9 | Windows 확장 | Tauri + Python 사이드카 | 웹/데스크톱이 같은 FastAPI를 쓰도록 API 경계를 지금부터 유지. |

## 2. 전체 개발 순서

1. 아키텍처 확정 & 웹 3D 편집기 골격 ← **완료 (1~7일 차)**
2. Python CAD 엔진(FastAPI + CadQuery) 연동, 메시 반환
3. AI 자연어 → CAD JSON 명령 (질문 기능 포함)
4. 직접 편집과 AI 수정 통합 (같은 명령 경로)
5. STL·3MF 내보내기 + 형상 검사 + 실제 출력 테스트
6. 프로젝트 저장/불러오기, 상용화 준비

## 4. 핵심 마일스톤

“웹 화면에서 큐브를 만들고, AI에게 ‘높이를 50mm로 바꿔줘’라고 하면 실제 모델이 변경”

- 화면 → 명령 → 모델 반영 경로: **완료** (`set_params` 명령, 속성 패널에서 검증됨)
- 남은 것: LLM이 `{"type":"set_params","target":"box_1","params":{"height":50}}`를 생성하도록 하는 3주 차 작업. 실행 경로는 이미 동일하다.

### 6일 차 결과 메모
- `create_cylinder`, `create_sphere`, `create_cone` 추가 (기획서 초기 명령 목록의 원뿔 포함).
- `set_params` 는 대상 도형 종류에 따라 허용 키를 검사하고, 수정 후 객체 전체를 다시 검증한다 (원뿔 반지름 규칙 등).
- 명령 스키마의 모든 객체를 strict 로 변경: 알 수 없는 필드는 거부 → LLM 이 지어낸 필드가 조용히 무시되지 않음.
- `npm run schema:export` → `shared/schemas/*.schema.json` 생성. 커밋된 파일이 코드와 다르면 테스트 실패(드리프트 방지).
- `shared/schemas/examples/` 의 공유 픽스처 25개에 대해 Zod 와 Python `jsonschema` 가 같은 판정을 내림을 확인.
- E2E 불안정 원인 분석: 앱 문제가 아니라 테스트가 재렌더 전 값을 즉시 읽던 경쟁 상태 → 자동 재시도 단언으로 수정, 병렬 반복 20/20 통과.

### 7일 차 결과 메모
- Python 3.12 고정 (CadQuery/OCP 휠 지원 3.11–3.14 중 패키징 생태계가 가장 안정적인 버전). 패키지 관리는 uv.
- Pydantic 모델을 Zod 와 같은 계약으로 작성. 숫자 strict(문자열·bool·NaN 거부), 미정의 필드 거부, 명시적 null 거부.
- 계약 테스트: 공유 예제 29개에 대해 Zod / JSON Schema / Pydantic 세 검증기가 같은 판정, 명령별 필드·필수 여부 일치 검사.
  - 이 과정에서 발견해 고친 차이: 빈 params(JSON Schema 통과), 선택 필드의 null(Pydantic 통과), 공백뿐인 이름(JSON Schema 통과).
- 검증 API 는 200 + `{ok, issues}` 형식, 오류 메시지 한국어, 경로 포함 (예: `params.height`).
- 요청 크기 1MB 제한 (chunked 전송 포함), 객체 수 1000개 제한 (양쪽 동일).
- 프론트엔드: 10초마다 상태 확인, 모델 변경 시 400ms 디바운스 후 검증, 이전 요청 취소, 서버 응답도 Zod 검증.
- 백엔드가 꺼져 있어도 편집기는 정상 동작 (확인함).

### 2주 차 결과 메모
- CadQuery 2.8.0 (OCP 7.9.3). import 약 5초 → 미리 띄운 워커 풀. 가상환경 약 1.7GB (배포 시 최적화 과제).
- 실험으로 잡은 OCCT 함정: 같은 반지름 원뿔은 오류 → 원통으로 생성 / `makeSphere` 기본값은 반구 → 각도 명시.
- 회전: CadQuery 결과가 Three.js Euler XYZ(Rx·Ry·Rz)와 일치함을 꼭짓점 비교로 검증.
- 서버 메시는 객체 로컬 좌표 + 형상 키 캐시 → 이동/회전/실행 취소 시 재계산 없음.
- 불리언: 파라메트릭 트리 구조 (위 아키텍처 문서 참고). 프론트↔백엔드 변환 합성 일치를 공유 픽스처로 검증.
- STL: 직접 작성한 바이너리 STL. 테스트로 치수·부피(법선 방향)·닫힌 메시(모든 모서리 2회 공유) 검증.
- **남은 사람 확인:** 실제 슬라이서(Cura/PrusaSlicer/Bambu Studio)에서 열어 치수 확인 및 출력 테스트.

- 거절(refusal)은 내용보다 먼저 확인, `fallbacks: "default"` 사용. Opus 5.5 의 강제 도구 호출 금지 규칙 준수(auto + 프롬프트).
- BYOK 키는 로컬 데이터 폴더(0600), 응답에는 끝 4자리만. 사용량·예상 비용 JSONL 기록, 가격표 수정.
- 프론트: AI 요청 1건 = `dispatchBatch` = 실행 취소 1단계(원자적). 질문 선택지 버튼, 요청별 비용, 이번 달 합계, 설정 창.
- 발견·수정: 보낸 직후 포커스가 채팅 입력창에 있어 Ctrl+Z 가 글자 실행 취소로 처리됨 → 입력창이 비어 있으면 모델 실행 취소.
- 평가: 케이스 10개, 실제/녹화/재생 모드. 이 개발 환경에는 API 키가 없어 실제 실행 기록은 아직 없음.

## 25. 스케치 보강 (형식 v13) — ✅ 완료

- 호 변: 다각형·경로의 변 k 를 볼록 정도 `bulge = tan(호 각도/4)`(−1~1, ±1 = 반원, 양수 = 변 방향 오른쪽으로 볼록 — 반시계 다각형의 바깥)
  의 원호로 (`arcs: [{k, bulge}]`, 명령 `set_arc`, 0 = 직선). 곡선 규칙 `curves.ts bulgeArc` ↔ `curves.py bulge_arc`.
  정밀 엔진(OCCT·CadQuery)은 정확한 원호, 메시 엔진은 π/32 간격 표본. 호 변에 붙은 꼭짓점은 필렛·모따기 불가(오류 안내).
- 사각형 → 다각형 (`convert_to_polygon`): 같은 id, 왼쪽 아래부터 반시계 네 꼭짓점. 사각형 치수와 그 요소를 참조하는 구속은 지운다.
- 대칭 구속 `symmetric [점, 점, 변]`: 두 점의 가운데가 축 위, 두 점을 잇는 선이 축에 수직 (해석기·서버 검증이 같은 잔차). 구속 참조는 최대 3개.
- 화면: 다각형 변마다 볼록 정도 입력, 꼭짓점 처리에서 꼭짓점별 체크(안 고르면 전체), 두 대상 구속에 '대칭'(셋째 칸 = 축), 사각형 '다각형으로 바꾸기'.
- 형식 v12 → v13 읽기: 내용 그대로, 버전만 올림. 공유 픽스처 43가지 (v13: 반원 호 변 돌출, 바꾼 다각형 한 꼭짓점 필렛).

## 29. 스플라인 (형식 v16) — ✅ 완료

- 다각형·경로에 `spline: true` (명령 `set_spline`): 점들을 지나는 균일 Catmull-Rom 곡선을 구간마다 3차 베지어로
  (c1 = Pi + (Pi+1 − Pi−1)/6, c2 = Pi+1 − (Pi+2 − Pi)/6, 열린 곡선 끝은 가상 점 2·끝점 − 이웃). `curves.ts splineSegments` ↔ `curves.py spline_segments`.
- 정밀 엔진(브라우저 OCCT Geom_BezierCurve, 서버 cq.Edge.makeBezier)은 정확한 베지어, 메시 엔진은 구간당 24 등분 → 세 엔진이 같은 곡선.
  돌출·회전·쉘·로프트 단면(닫힘), 스윕 경로·리브(열림) 모두 같은 경로로 동작. 점은 그대로라 꼭짓점 편집·구속이 그대로 쓰인다.
- 켜면 꼭짓점 처리·호 변을 지우고, 스플라인에는 필렛·호 변을 거부. 오프셋 복사는 점을 띄운 근사.
- 스플라인 그리기 도구: 점 클릭 → 첫 점 다시 = 닫힌 곡선, 마지막 점 다시·Enter = 열린 곡선 (명령 묶음 1건).
- 공유 픽스처: 닫힌 스플라인 돌출, 스플라인 경로 스윕 (기준값은 베지어를 촘촘히 나눈 넓이·길이).

  끌기를 끝낸 클릭은 객체 선택으로 이어지지 않는다.
- `move_point` 가 사각형 모서리(형식 v21 참조)를 받으면 그 모서리가 목표에 오도록 중심을 옮긴다 (폭·높이 유지).
- 구속 기호 (`cad/sketchRelations.ts`): ⊕ 고정 · ● 일치 · ◎ 동심 · ― 수평 · ｜ 수직 · ∥ 평행 · ⊥ 직교 · ＝ 같은 길이 · T 접선 · ⇋ 대칭 · M 중간점,
  길이·거리·각도 값, 사각형 폭·높이·원 지름. 같은 자리는 한 묶음. 설정 막대 "구속 표시"로 끄기.
- 검증: 단위(기호 위치, 모서리 끌기로 중심 이동 + 일치 구속 따라옴), E2E (모서리 (20,10)→(25,15) = 중심 (5,5), 실행 취소, 기호 끄기).

## 44. 스케치 대칭·패턴 복사 — ✅ 완료

- 속성 패널 "대칭·패턴 복사": 요소를 골라 대칭 복사(세로·가로 축 또는 구성선), 직선 패턴(개수·간격 u/v), 원형 패턴(개수·중심·전체 각도).
- 순수 함수 `cad/sketchCopy.ts`: 결과는 보통의 요소 추가 명령(add_rectangle·add_polygon·set_arc·set_corner·set_spline …) — 저장 형식 그대로.
  대칭은 다각형·경로 점 순서를 뒤집어 반시계 유지(호 변·꼭짓점 처리 번호도 옮김), 슬롯·타원 각도 반전.
  사각형이 기울어지는 경우(비스듬한 축·45° 회전)는 다각형으로.
- 구성선 축 대칭은 원본·복사본 점마다 대칭 구속 → 원본을 끌면 복사본이 따라온다 (모순되는 구속은 건너뜀). 복사 전체 = 실행 취소 1번.
- 검증: 단위(축 대칭·각도·호 번호, 대칭 구속 따라오기, 90°/45° 회전), E2E (대칭 → 직선 패턴 → 실행 취소).

## 45. 스케치 잘라내기·연장 — ✅ 완료

- 스케치 탭 "잘라내기": 구성선·경로 위에 커서를 올리면 누른 자리 양옆 가장 가까운 교차점 사이 조각이 빨갛게 보이고, 누르면 지운다
  (교차점이 없으면 그 변 전체 — 경로는 두 조각으로 나뉜다).
- "연장": 구성선·경로 끝을 누르면 그 변 방향으로 가장 가까운 다른 요소까지 늘인다 (초록 점선 미리보기, `move_point` → 구속 유지).
- 순수 함수 `cad/sketchTrim.ts`: 교차는 원은 정확한 식, 사각형·다각형·호·스플라인·슬롯·타원은 촘촘한 꺾은선.
  결과는 기존 명령(delete_sketch_entity·add_line·add_path·move_point) — 저장 형식 그대로, 실행 취소 1번.
  호·둥근 모서리·스플라인이 있는 경로는 아직 대상이 아니다 (이유를 알려줌).
- 검증: 단위(가운데·끝 조각, 경로 변 통째로, 원까지 연장), E2E (사각형 안 조각 지우기 → 원까지 연장 → 실행 취소 2번).

## 46. 스컬프트 마스크 (블렌더 M · Alt+M · Ctrl+I) — ✅ 완료

- 마스크 브러시(M): 칠한 점은 다른 브러시(그리기·부풀리기·매끈하게·평평하게·잡아끌기)에 움직이지 않는다 (점마다 0~1, 감쇠만큼).
  Ctrl = 지우기, Alt+M = 전부 지우기, Ctrl+I = 뒤집기. 가린 곳은 어둡게 (점 색, 모디파이어가 없을 때).
- 마스크는 화면 상태(저장·실행 취소 대상 아님) — 점 수가 바뀌면(촘촘하게·편집) 없어진다. 모양을 바꾸지 않으므로 명령이 없다.
- 검증: 단위(가린 점 고정, 지우기, 잡아끌기도 마스크), E2E (Ctrl+I 로 전부 가리면 획이 아무것도 바꾸지 않음 → Alt+M 뒤 획이 됨).

## 47. 나이프·스냅 (블렌더 K · Shift+Tab) — ✅ 완료

- 나이프(편집 모드 K, 헤더 "나이프 K"): 화면에 선을 끌어 그으면 그 선을 지나 시선 방향으로 뻗은 평면으로 면을 자른다
  (고른 면이 있으면 그 면만, 없으면 전부). 원근·직교 모두 두 시선 줄을 품은 평면. Esc·오른쪽 클릭 취소.
- 새 메시 편집 `mesh_edit { op: 'bisect', faces, point, normal }` (형식 그대로 v22 — 메시 편집 종류만 추가, Zod·Pydantic 동시).
  `polymeshSelect.bisectFaces` 로 면을 둘로 나누고 이웃 면에도 새 점을 끼워 닫힌 메시를 유지한다. 실행 취소 1번.
- 스냅(Shift+Tab, 헤더 "스냅"): G/R/S 조작 중 단위(이동 1mm · 회전 5° · 크기 0.1배) 또는 "점에 붙기"(화면 20px 안 가장 가까운 다른 점).
  조작 중 Ctrl = 이번만 반대 (블렌더와 같음). 화면 상태 — 저장하지 않음.
- 검증: 단위(가로지르는 평면 → 옆면 4개가 8개, 닫힘 유지, 안 닿는 평면은 그대로), E2E (스냅 G 결과가 정수 mm,
  정면 보기에서 가로선 → 면 10개·닫힘 → 실행 취소).

## 48. DXF 가져오기 (2D 도면 → 스케치) — ✅ 완료

- 툴바 "가져오기"에서 .dxf 를 고르면 XY 평면에 파일 이름의 새 스케치, 스케치 속성 "DXF 가져오기"는 고른 스케치에 더한다. 전체 = 실행 취소 1번.
- 순수 함수 `cad/dxfImport.ts` (ASCII DXF): LINE · ARC · CIRCLE · LWPOLYLINE · POLYLINE · ELLIPSE · SPLINE(de Boor 샘플).
  끝점이 맞닿는 선·호를 이어 닫히면 다각형(반시계, 돌출 가능), 열리면 경로. 호는 bulge 그대로(같은 규칙), 반원 넘는 호는 나눔.
  전체 타원 = 타원 요소, 원 = 원 요소. 단위 $INSUNITS(인치·피트·cm·m → mm), -Z 돌출 방향(OCS)은 x 반전.
- 결과는 기존 명령(add_polygon·add_path·set_arc·add_circle·add_ellipse) — 저장 형식 그대로 v22.
  점 64개 넘는 닫힌 윤곽은 경로로 나누고, 요소 한도(100)·읽지 않은 요소(TEXT·INSERT·HATCH …)는 알림에 적는다.
- 검증: 단위 8개(사각형 사슬·반시계, bulge·인치, 270° 호, 반원 둘 원, |bulge|>1, 스플라인, OCS, 한도), E2E (판+구멍 DXF → 영역 돌출 → 슬롯 DXF 더하기 → 실행 취소).

## 49. 스케치 텍스트 (각인·양각) — ✅ 완료

- 스케치 속성 "텍스트": 글자·크기(em, mm)·가운데 좌표 → 글꼴 윤곽을 닫힌 다각형으로 넣고 영역 하나(`text_regionN`)로 묶는다.
  영역 돌출 = 양각, 돌출 컷 = 음각(면 위 스케치). 줄바꿈 가능. 전체 = 실행 취소 1번. 저장 형식은 그대로 v22 (보통의 다각형·영역).
- 글꼴: Noto Sans KR Bold (OFL-1.1) 서브셋 438KB — 영문·숫자·기호 + KS X 1001 한글 2,350자. 프로그램에 함께 들어 있고(오프라인),
  텍스트를 처음 넣을 때만 opentype.js(MIT)와 함께 불러온다 (첫 화면 크기 영향 없음). 글꼴에 없는 글자는 넣기 전에 알려준다.
- 순수 함수 `cad/sketchText.ts`: 곡선(2·3차 베지어)을 크기에 맞춰 나누고 Douglas–Peucker 로 윤곽마다 점 64개 이하.
  영역 순서 = 넓이 큰 것부터, 합치기/빼기 = 가장 큰 윤곽과 같은 방향이면 합치기·반대면 빼기
  → 겹친 획(가변 글꼴 출신 정적 글꼴에 흔함)은 합쳐지고 'O'·'ㅇ' 의 속은 빠진다.
- 영역 항목 한도를 20 → 100 (스케치 요소 한도와 같게, Zod·Pydantic 동시) — 기존 파일은 그대로 유효.
- 한계: 넣은 글자는 다시 고칠 수 없는 윤곽 (지우고 새로 넣기), 한 스케치에 윤곽 99개까지(한글 약 20자).
- 검증: 단위('O' 구멍, 'A' 겹친 획, '안녕' ㅇ 속 빼기·점 한도, 여러 줄, 없는 글자, 한도 경고), E2E (없는 글자 안내 → "AI 3D 한글" → 영역 돌출 크기 → 실행 취소),
  정적 웹·오프라인 E2E (글꼴이 번들에서 읽힘, 외부 요청 0건).
