# 검토: 2D 스케치 구속 해석기 (라이선스·크기·통합 방식)

상태: **검토 (구현 전)** · 2026-11-03 · 현재 스케치는 "치수형 사각형·원 + 고정 치수"만 있다 (구속 해석기 없음).

## 1. 무엇이 필요한가

직선·호·점이 섞인 일반 스케치에서 **일치·수평/수직·평행·직교·같은 길이·거리·각도·접선·동심** 같은 조건을 동시에 만족하는 좌표를 구하는 기능.
상용 배포(웹·Windows, 소스 비공개 가능성)를 전제로 라이선스를 먼저 본다.

## 3. 라이선스 판단

- **GPL(SolveSpace)**: 제외. 앱을 GPL 로 공개할 계획이 없다면 쓸 수 없다.
- **LGPL(planegcs)**: "라이브러리를 사용자가 교체할 수 있게 별도 파일로 배포 + 고지 + 소스 입수 방법"이면 비공개 앱과 함께 배포 가능하다는 것이
  일반적 해석이다 (지금 OCCT·casadi 를 별도 DLL 로 배포하는 방식과 같은 원칙). 다만
  - 웹: 별도 `.wasm` 파일 + 공개 소스 링크로 "교체 가능"을 충족하는지에 대한 확립된 판례·합의가 없다.
  - 우리 코드가 WASM 안에 정적으로 들어가면 안 된다 (지금처럼 npm 패키지 그대로 별도 파일로 로드해야 함).
  → **상용화 전 법률 검토 필요.** 기술적으로는 OCCT 와 같은 방식(별도 파일, 고지, 수정 금지 또는 수정본 소스 공개)으로 맞출 수 있다.
- **BSD / 자체**: 제약 없음.

## 4. 구조 제안 (어느 해석기를 쓰든 공통)

- **해석기는 편집할 때 프론트엔드에서만 돈다.** 설계 원본에는 구속 조건과 함께 **풀린 좌표를 저장**한다.
  → CAD 엔진(서버 CadQuery·브라우저 manifold)은 지금처럼 명시적 좌표만 읽는다. 백엔드에 해석기가 필요 없고, 두 엔진이 같은 결과를 내는 규칙도 그대로.
- 명령: `add_line`, `add_arc`, `add_constraint {type, refs, value?}`, `remove_constraint`, `set_dimension`(치수 구속 값).
  실행기가 해석기를 호출해 새 좌표를 계산하고, 풀리지 않으면(과구속·모순) **원본을 바꾸지 않고 거부**한다 — 지금의 명령 경로와 같은 원칙.
- 해석기 인터페이스를 `features/sketch/solver.ts` 뒤에 두어 자체 ↔ planegcs 를 바꿀 수 있게 한다 (플랫폼 차이를 인터페이스 뒤에 두는 기존 규칙과 같음).
- 지금의 치수형 사각형·원은 "구속이 미리 정해진 도형"으로 그대로 유지한다 (형식 호환).

## 5. 권장

1. **1단계: 자체 해석기(TypeScript)로 시작** — 범위: 점·직선·원·호, 일치·수평·수직·평행·직교·같은 길이·거리·반지름·동심·접선(직선-원).
   이 정도는 레벤버그-마쿼트 + 자유도 계산으로 구현 가능한 크기이고, 라이선스 위험이 없다.
   검증: 구속별 단위 테스트 + 무작위 초기값에서 수렴률 측정 + 과구속·모순 진단 메시지.
2. **planegcs 는 대체 후보로 유지** — 자체 해석기의 수렴·성능이 부족하면, 법률 검토 후 같은 인터페이스 뒤에 교체.
3. SolveSpace 계열은 쓰지 않는다.

## 6. 결정이 필요한 사항

1. 1단계를 자체 해석기로 할지 (권장) / planegcs 를 법률 검토 후 바로 쓸지.
2. 1단계 구속 범위 (위 5-1 목록).
3. 상용 배포 형태 확정 시 LGPL 구성 요소(OCCT·casadi·planegcs 후보) 법률 검토를 한 번에 받을지.
